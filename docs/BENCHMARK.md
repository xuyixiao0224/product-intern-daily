# Benchmark: xhs-job-monitor vs Product Intern Daily

> 状态：**5 条真实 LLM 预跑已完成**；30–50 条正式 benchmark 待跑。monitor 使用真实 DeepSeek `deepseek-chat`，本地 fake Feishu + `xhs` shim。

## 目的

比较“同一条帖子，两个管线能拿到什么”，而不是比较谁更会写 prompt。

## 语料

- 同一批 30–50 条产品实习帖（含正文、图片、评论、置顶评论）；
- 人工标注 ground truth：公司、岗位、Base、邮箱、是否在招/截止；
- 不公开真实邮箱，报告里用 `post_id` + 统计。

## 指标

| 指标 | 说明 |
|---|---|
| 联系方式覆盖率 | 有邮箱/内推码/有效投递链接的比例 |
| Base 覆盖率 | 能给出 Base 的比例 |
| 状态覆盖率 | 能给出在招/截止的比例 |
| 图片/评论-only 邮箱 | 正文没有、只在图片/评论里的邮箱数量 |
| 字段准确率 | 与人工标注一致的比例 |
| 运行时间 | 单条平均耗时 |
| 依赖 | 是否需要 LLM Key、飞书、OpenClaw/Codex |
| 成本 | 每条帖子 LLM token/费用 |

## 方法

1. 固定同一批帖子 ID；
2. monitor 用真实 LLM（OpenAI-compatible endpoint）+ 真实/模拟飞书；
3. 本项目和 monitor 各跑一遍；
4. 人工标注 + 双人复核；
5. 只报告统计和匿名样例，不公开个人邮箱。

## 当前 5 条预跑（非正式）

- monitor：5 条记录，1 个联系方式；
- 本项目：5 条记录，5 个邮箱，3 条在招，1 条已截止。

> 5 条预跑已使用真实 LLM；仍只有 5 条，**不作为最终结论**，正式版需 30–50 条 + 人工标注。

## 20 条固定搜索“产品实习”预跑（真实 LLM）

- monitor：20 条输入，4 条入库，3 个联系方式；
- 本项目：20 条输入，6 条入库，3 个邮箱，0 条在招（样本里作者未回复状态）；
- 结论：这 20 条里没有“图片/置顶评论-only 邮箱”，所以联系方式数量打平；monitor 过滤更激进，我们保留更多“未识别但正文有产品 JD”的帖子。
- 5 条 curated（含 P2/置顶评论图片邮箱）：monitor 1/5，本项目 5/5。

> 两个样本不能合并成单一准确率；正式 benchmark 仍需 30–50 条 + 人工标注。
